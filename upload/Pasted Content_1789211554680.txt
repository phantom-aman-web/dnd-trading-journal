DnD BACKEND + DATABASE REBUILD
AUTHORITATIVE FINANCIAL ENGINE + ANALYTICS ENGINE SPECIFICATION

You are rebuilding the DnD backend, database, persistence layer, calculation engine, and analytics layer from scratch.

The current frontend/product is valuable and should remain the product-facing source.

The old backend implementation is REFERENCE ONLY.

Do NOT blindly copy its database model, calculation formulas, API logic, or analytics implementation.

I have identified multiple conceptual problems in the old implementation, especially around instrument monetary semantics, partial exits, aggregation scope, checklist adherence, and analytics definitions.

The purpose of this task is to establish ONE authoritative data model, ONE authoritative financial calculation model, and ONE authoritative analytics model.

============================================================

1. The backend is authoritative.
2. The database is authoritative for persisted state.
3. The client never supplies authoritative calculations.
4. The client never supplies authoritative status.
5. The client never supplies authoritative analytics.
6. Every financial value must have an explicit unit.
7. Every calculation must have one canonical implementation.
8. Every analytics metric must have one canonical definition.
9. Every persisted field must survive:
   form

   -> login again

13. Partial trades must never be silently counted as fully closed trades.
14. Checklist adherence must never be inferred from win rate.
15. A successful API response is NOT proof of correctness.
16. A successful database write is NOT proof of correct semantics.
17. Every metric must be testable from known input data.

5. FIX INSTRUMENT SEMANTICS
============================================================

The previous implementation mixed:

- tick value
- point value
- contract size

This must not happen again.

Choose a single authoritative model.

Recommended model:

contractSize:
underlying units represented by one quantity unit OR the contract multiplier.

pointValue:
monetary value of ONE FULL PRICE UNIT for ONE contract/quantity unit, expressed in account/base calculation currency.

tickSize:
minimum price increment.

tickValue:
derived value of one tick.

DO NOT use a field named pointValueCents to secretly mean tick value.

If a value represents tick value, call it tickValueCents.

If it represents full-point monetary value, call it pointValueCents.

Never mix them.
