# 3. MOST IMPORTANT PRODUCT FIX: REAL A+ SETUP SCORING

This is the highest-priority product correction.

The current application visually contains an A+ setup/checklist system, but the current score is effectively determined from the selected grade rather than from the actual checklist answers.

For example, the current behavior is conceptually similar to:

```text
A+ → 0.92
A  → 0.80
B  → 0.62
C  → 0.45
```

That is not acceptable.

The application must actually **evaluate the setup**.

## Required behavior

The trader should be presented with the applicable checklist when evaluating a trade.

A checklist may contain weighted conditions such as:

```text
HTF Bias aligned                 15%
Liquidity taken                  15%
MSS/BOS confirmed                15%
Displacement                     15%
FVG / entry model                15%
Session alignment                10%
Target liquidity identified      10%
Risk rules satisfied              5%
```

The exact weights and checklist items should remain configurable through the application's existing checklist/strategy infrastructure.

The important behavior is:

```text
raw checklist answers
        ↓
weighted calculation
        ↓
score
        ↓
derived grade
```

For example:

```text
8 / 8
= 100%
= A+
```

or:

```text
6 / 8
= 75%
= A
```

The precise grade boundaries should come from a clear, consistent rule in the application's configuration/domain logic rather than being hardcoded in UI components.

## Critical rule

The user must **NOT manually choose the final grade**.

The application calculates the grade.

The user only supplies the underlying checklist answers.

The resulting grade should be derived from those answers.

# 5. CHECKLIST VERSIONING

Checklist definitions must be historically stable.

If a trader changes a checklist later, previous trades must not silently change their historical score.

For example:

```text
Checklist v2.1
```

is used on a trade.

Later:

```text
Checklist v2.2
```

is created.

The old trade must still point to the exact checklist definition/version it used.

Store enough immutable information to reproduce the historical calculation.

Historical trade evaluation must therefore remain explainable.

A historical trade should be able to answer:

```text
Which strategy version?
Which checklist version?
What were the answers?
What weights were used?
What score was calculated?
What grade resulted?
```

Do not recalculate old historical grades from today's checklist definition.
