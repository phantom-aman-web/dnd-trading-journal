DnD CURRENT-PROJECT ENHANCEMENT PASS

IMPORTANT:
This is an enhancement of the CURRENT DnD application.

Do NOT rebuild DnD.
Do NOT replace the current architecture.

1. CENTRALIZED INSTRUMENT / SYMBOL SYSTEM
--------------------------------------------------

This is one of the most important changes.

Currently, several areas ask the user to enter an instrument, pair, or symbol.

Create ONE consistent instrument-selection system that is reused everywhere.

Do not create different symbol logic for:

- Settings
- Add Trade
- Accounts
- Analytics
- Calendar
- Journal
- anywhere else

There should be a single source of truth for instruments.

Inspect the existing Instrument model/data and extend it rather than creating duplicate models unless absolutely necessary.

--------------------------------------------------
1A. SYMBOL INPUT
--------------------------------------------------

Wherever the user can manually enter a symbol/instrument:

- automatically convert entered characters to UPPERCASE
- prevent lowercase from being stored
- normalize leading/trailing whitespace
- validate against the known instrument catalog where appropriate
- preserve the ability to handle a custom instrument if the current application supports custom instruments

Examples:

eurusd → EURUSD
xauusd → XAUUSD
nas100 → NAS100

Do this both:
- in the UI
- on the server

The server must remain authoritative.

Do not rely on CSS/text-transform alone.

--------------------------------------------------

When the user selects an instrument during trade logging, automatically use that instrument's metadata to determine:

- decimal places
- pips / points / ticks where applicable
- quantity representation
- position-size behavior
- risk calculation
- stop distance
- target distance
- P&L calculation
- R multiple

INDEX FUTURES:
- ticks / points
- contract multiplier

Do NOT use a single universal "pip" calculation for every market.

Do NOT use arbitrary hardcoded point values.

Use the centralized instrument definition.
